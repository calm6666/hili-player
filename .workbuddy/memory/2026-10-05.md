## 项目架构调研（首次全量梳理）

对 hili-player 做了一次完整的架构与实现分析，结论备份如下（代码量按实际统计）：

### 规模
- core/ 自研框架 4666 行；packages/player/src 29664 行（含 scss 10129 行，26 个文件）；
  packages/plugins/src 19784 行；plugins/vite-plugin-hili-compile 1035 行；tests/ 5200 行。
- git 仅 8 次提交，最近一次是「提交工作区全部改动」，工作区干净。

### 分层与机制
- 五层：宿主/演示 → packages/player → packages/plugins → core/ → types+工程化。
- 核心机制「零 diff」：挂载期 h()/编译宏 → VNode 普通对象 → materialize 递归 createElement → 真实 DOM；
  运行期 signal.set() → effect → 开发者手动改原生 DOM，框架不做重渲染、不做 key diff。
- 编译期：vite-plugin-hili-compile 用 babel + MagicString 把 h() 改写成 `_createEl/_createStaticEl/_createSvgEl/_createFragment/_createComp`，
  dev/prod 同一套产物，prod 额外做静态提升 hoistStatic + `_cloneHoisted`。
- 运行时状态三套并存：TypedStateManager（内存路径式）/ PlayerStore（localStorage 持久化）/ TypedEventBus（纯事件）。
  另有 PluginManager 私有的一套 state/events/hooks。StateManager 用微任务批量调度，EventBus 强制同步 + try-catch（事件间有依赖）。
- 插件：Plugin 接口 + PluginManager + PluginContext；流媒体侧经 `utils/media/streamMiddleware.ts` 统一转发。
